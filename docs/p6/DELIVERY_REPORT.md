# P6 确定性与回放交付报告

在训练场以 F8 开始或结束录制，F10 保存，重新启动后以同一阵容按 F11 读取。模拟器能独立检查同一个文件，不需要 Godot 或原角色包。命令行也能以指定种子录制双人、组队和四人混战的输入脚本。[操作指南](../p6/REPLAY.md) · [版本任务书](../p6/TASK_V1.md) · [架构决议](../architecture/ADR-009.md)

## 验证结果

- Rust 在已提交帧捕获完整战斗规则、随机流、动作、投射物和结算状态。QA 从同帧互殴、连招、换线等八个时点恢复，后续每一帧的哈希、选手、投射物及事件与连续运行一致。
- 独立运行的编辑器与 macOS ARM64 导出程序分别录制、存盘并重新启动回放。CLI 对实测 25 帧的训练录像给出一致的末帧哈希。最大长度 36,000 帧的录像也能从磁盘回放至相同末态。
- 修改第 80 帧的行走输入，CLI 报告首个分歧为第 80 帧，并输出预期与实际哈希。同时修改多帧的用例也定位到最早受影响的帧。QA 发现的损坏录像覆盖旧录制问题已修复，导入在后台完整验证成功后才替换对局。
- 84 项 Rust 测试与 3 项 CTest 通过，两项单独运行的性能和内存测试通过。图形、跨进程和边界测试结果见[独立 QA 报告](../testing/P6_ACCEPTANCE_REPORT.md)及[原始观测数据](../testing/evidence/p6-replay.json)。

## 性能与使用边界

M1 Max 的真实训练窗口限速 60 FPS，两轮各采集 600 个绘制间隔。录制平均 60.021 FPS，回放平均 60.002 FPS。最长绘制间隔 31.487 ms，物理处理最高 3.090 ms，仍有个别绘制帧超过 16.67 ms 的预算。

四人原生回放步进及哈希的 P99 为 3.875 微秒。一个含飞行道具的四人快照占用 5,488 字节，重复创建并释放 1,000 次，分配计数均回到基线。36,000 帧训练录像为 10,898,446 字节，本机后台读取验证耗时约 84 毫秒，保存约 53 毫秒，期间暂停战斗并继续绘制。

录像格式为 OFE_REPLAY v1。训练使用一个本地存档槽；保留多段录像可复制文件。图形性能测量来自上述 Mac，其他机器的逐帧显示表现需要实机测量。P6 待项目负责人验收。[P5 交付归档](../p5/DELIVERY_REPORT.md)
