# P2 实施方案

负责人签收 P1 后，以 38bb8ab 为基线开展 P2。ADR-005 冻结按实体 ID 提交指令的接口、逐帧时序、队伍过滤和结果顺序。P1 的 Duel 作为适配入口，使用相同的 Arena 结算，P0 的 C ABI v1 用作回归控制。

|工作包|职责与交付|
|---|---|
|Architecture|定义招式窗口、hitstop、护甲、能量和多人结算语义|
|Combat Core 与 Tech Lead|整数动作推进、接触收集、稳定排序及原子提交|
|Simulator|OFC 补充配置、2v2 / FFA 的终端输入和复现脚本|
|独立 QA|逐项测试矩阵，验证边界、同帧资源竞争、乱序输入和回归|
|Tech Lead|全平台构建、真实运行、基准、证据与交付审查|

重点风险为窗口差一帧、溢出后部分提交、同一投射物多次命中、命中停顿影响取消输入、队友伤害与阵容排列偏置。分别使用边界用例、错误后继续推进、稳定 ID 和逆序重复同一战局检查。P3 的通用资源加载及 P4 的 Godot 战斗画面后续另行签收和授权。
