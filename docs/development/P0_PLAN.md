# P0 实施方案与分工

P0 仅验证从编号输入到权威状态，再到 Godot 展示的最短真实链路。验收按总任务书第十七章逐项执行。工程历史与依赖基线见[初始化前审计](INITIAL_AUDIT.md)。

|工作包|职责|进入下一步的证据|
|---|---|---|
|P0-01 架构|Architecture 复核接口，Tech Lead 冻结并集成|ADR 明确字段、单位、帧时序、错误码、调用方内存与兼容策略|
|P0-02 仓库|Build & DevOps 建立 Cargo、CMake、Godot 工程与 CI|干净工作树按锁定版本解析并构建|
|P0-03 桥接|Godot Integration 实现 ABI、类型适配、场景|真实 Godot 宿主完成创建、提交、推进、读取、销毁及错误调用|
|P0-04 格式|Architecture 与 Asset 职责共同定义 Schema、资源图及样例|四格式分别通过合法用例，非法用例输出定位信息|
|P0-05 核心|Combat Core 仅实现帧推进、坐标、事件及快照骨架|依赖图独立于 Godot，确定性、恢复与错误原子性有回归用例|
|P0-06 测试|QA 在独立工作树验证，开发者修复缺陷|独立重建、宿主调用、失败日志与复测记录|
|P0-07 构建|Build & DevOps 构建四个目标并验证导出|分别记录编译器、目标架构、产物和实际运行环境|
|P0-08 交付|Documentation 汇总使用指南，Tech Lead 审查集成|状态、依赖、许可证、性能、QA 与交付记录可追查|

执行顺序为仓库审计、工程初始化、架构起草与复核、冻结、按模块并行实施、集成、独立复测和负责人签收。架构复核前已派发的依赖实现任务曾暂停，待 ADR-002 冻结后恢复。开发者在职责分支或 worktree 提交 Conventional Commits，主控合并；发生接口歧义时由 Architecture 提交 ADR，Tech Lead 统一决定。总纲列明的重大变更须先取得项目负责人决策。[项目治理](../governance/README.md)

当前使用本地 Git。GitHub 托管 CI 的实际运行记录须在项目负责人自行关联远端后取得。架构、ABI、干净构建与各目标的验证风险见[风险与验证方法](../architecture/overview.md)。QA 提交独立意见，项目负责人决定是否签收；任何阻塞项均保留对应状态和证据。
