# ADR-006 · P3 角色、动画与资源运行时

P3 保留 OFC/OFA 1.0、外置 OFE_MOVE_PROFILE 1.0、Combat Core、Godot ABI v1 和已有模拟器命令。P3 的交付路径为“用户提供的目录或 .ofc → 完整校验 → Rust 动画播放 / 战斗配置 → 既有 Arena”。角色内容可在编译后替换。P4 承担 Godot 显示。

## 公共入口与归档

现有 `python tools/ofe-validator/ofe.py` 为作者 CLI。保留 `validate FILE`，另支持 `validate DIR|PACK.ofc`、`package DIR OUTPUT.ofc`、`inspect DIR|PACK.ofc` 以及 `run DIR|PACK.ofc --simulator EXE [--script FILE]`。run 将合法目录或临时展开目录直接传给外部可执行文件 `EXE --character DIR [--script FILE]`，继承标准流与子进程退出码。该模式复用双人逐帧文本输入，两个对手从指定包创建，普通攻击采用 manifest.moves[0]，场景参数来自现有演示配置。Rust CLI 可直接运行目录；.ofc 的支持由 Python 入口完成。原有内置样例与 --mode 2v2/ffa 继续可脱离源码树运行。

目录与 ZIP 根均含 manifest.json，文件相对引用保持原有层级。可选的根文件 move_profile.json 对应 ADR-005，存在时与 manifest 的动作 ID、有效区间及取消目标交叉校验；缺省按 strike 和连续有效窗解释，存在无目标的取消窗口则报错。包内容为 manifest 可达资源加可选 profile，包含许可证。ZIP 由 Python 标准库读写，支持 stored 和 deflated；写入按路径排序，固定时间，产物成功后原子替换。解包到私有临时目录，释放时清理；拒绝绝对或越界路径、链接、重复/大小写冲突路径及超限成员。单个文件上限 64 MiB、总展开上限 256 MiB，最多 4096 个成员；以流式实际大小校验。校验/打包/检查错误码按已有 0/1/2，失效输出不得伪装成成功产物。

## Rust 边界

- `ofe-resource-runtime` 只处理本地资源。冻结 `ResourceStore::open(root: &Path) -> Result<Self, String>`、`read(&mut self, owner: &str, reference: &str) -> Result<Arc<[u8]>, String>`、`clear(&mut self)`、`cached_count(&self) -> usize`。owner 是包内引用文档路径（如 animations/idle.json），reference 相对 owner 的父目录；同一规范文件的重复读取共享 Arc。clear/drop 释放缓存所有权，现存 Arc 可继续读取。读取拒绝越出文档目录的引用及失效文件。缓存为单次装载快照，显式 clear 后允许重读。
- `ofe-animation-runtime` 依赖资源层。冻结 `Clip::load(store: &mut ResourceStore, path: &str) -> Result<Clip, String>`（path 为包根相对路径）、`Player::new(clip: &Clip) -> Player<'_>`、`frame_index(&self) -> usize`、`tick(&mut self) -> &[String]`、`finished(&self) -> bool`。创建后展示第 0 帧。第一次 tick 消费第 0 帧第一个时间单位并发出其进入事件，每次 tick 的事件和 frame_index 均对应本次展示帧；按 duration 精确展示 N 次。非循环的最后一帧展示满后 finished=true，后续持帧且无新事件。循环再次进入首帧时重新发事件。公开每帧原点、资源及图集源矩形（PNG IHDR 尺寸、行优先网格、整除校验）。事件不得反向改变战斗。P3 不依赖 Godot 或 GPU 解码。
- `ofe-character-runtime` 依赖资源、动画与核心，读取 manifest、属性、招式、判定框、动画及资源，验证版本、引用及 ID，保留 manifest 招式次序。冻结 `Character::load(root: &Path) -> Result<Character, String>` 和公开只读访问量（可用字段或 getter）id、属性、已解析招式、动画。对战适配复用已有 P1/P2 数据映射、精确 JSON 整数解析以及核心的配置验证；任一无效资源都使角色装载整体失败。角色存储与核心模拟实例各自拥有数据。资源/JSON/文件 I/O 不进入 combat-core。CLI 完整 Schema 与引用验证沿用 Python 实现；Rust 公共装载入口须独立检查影响运行的结构、范围、路径和缺失引用。
- Python 的 inspect 输出结构化 JSON，包含角色 ID、招式和动画 ID、作者与许可。验收至少比较目录和 .ofc 装载相同角色的真实模拟输出、外部属性/伤害改变后的结果、序列/图集的时间与事件、释放后重载及归档错误诊断。

## 并行文件边界

资源与动画负责人拥有 engine/resource-runtime、engine/animation-runtime。角色与模拟器负责人拥有 engine/character-runtime、tools/ofe-sim，迁移共享映射并保持既有测试。CLI 负责人拥有 tools/ofe-validator、打包及格式集成测试。主控独占根 Cargo.toml、Cargo.lock 与 CI；QA 使用独立黑盒夹具和干净目录复核。公共接口修订须由主控记录。
