# ADR-010 · 第三方角色、动画与离线项目启动

P7 沿用 OFC、OFA、OGP、OFL 的 1.0 Schema、P3 资源路径规则、P5 的公开 OFEMatch 和 60 Hz 战斗入口。作者通过两个独立的 MIT Rust crate 生成标准数据。角色 SDK 的输出包含清单、角色信息、属性、招式及框。动画 SDK 支持序列图、图集和帧元数据。示例 Rust 工程以外部路径依赖调用 SDK，生成可编辑的 Rook 角色。生成物通过相同的 Python 工具校验、打包并交给运行时。代码在制作阶段执行，游戏加载数据。[总纲 P7](../governance/PROJECT_CHARTER_V1.0.md)

## CLI 与游戏的边界

`launch PROJECT --runtime EXE [--mod SOURCE]...` 接受 OGP 项目或发布归档，追加的 SOURCE 为本地 OFC 目录或 .ofc 包。沿用本地资源图的版本、根目录及资源检查，先处理项目角色，再按声明顺序处理 Mod。重复的角色 ID 或不能满足的依赖会在启动前给出诊断。依赖声明允许随项目制作与分发。1.0 清单不含可供匹配的包版本，启动端对未解决的依赖报错。

CLI 在私有临时目录生成 `OFE_LAUNCH` v1 JSON 描述文件，传入 Godot 的用户参数为 `--ofe-project=<绝对描述文件路径>`。CLI 等待子进程退出后清理本次暂存。文件由 CLI 与同机子进程交换。分发格式使用 OGP/OFC 的相对资源引用。

|字段|含义|
|---|---|
|format / version|固定为 OFE_LAUNCH 与整数 1|
|title|项目标题|
|modes|按 OGP 顺序列出的 training、1v1、2v2、ffa|
|depth_projection|OGP 指定的非负纵深投影参数|
|characters|按选人顺序排列的数组。每项提供唯一 id、显示 name、指向已解析本地 OFC 的绝对目录 dir。|

Godot 根据启动描述生成角色名单、模式入口和投影设置。实际对战与训练仍从选中角色的本地 OFC/OFA 创建 Rust 对局，招式、帧数据和贴图沿用既有通道。普通启动保留内置游戏。OGP 中的资源按 Schema 校验并随项目封装。P7 游戏适配器支持的可见字段以上表为准。可视化编辑器和脚本插件不属本阶段接口。

## 验证

外部作者编译两个 SDK、生成角色、校验项目、打包后在不同目录解包启动。独立 QA 在编辑器与实际导出中通过 UI 选择追加角色，验证真实命中、生命、动画和模式。回归覆盖默认 P5/P6 游戏、非法版本、缺失资源、重复 ID、未解决依赖及项目归档往返。最终签收由项目负责人决定。
