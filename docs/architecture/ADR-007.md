# ADR-007 · P4 Godot 对战运行时

P4 将真实双人 Arena 接入 Godot 4.7.2。P0 的 ABI v1、OFEBattle、proof.tscn 与 P1 至 P3 的模拟器入口继续服务原调用方。角色选择、VS 流程、回合规则和训练菜单属于总纲 P5。P4 的技术场景在进入时创建双方角色，支持本地双人输入、回到初始对局、退出和再次进入。

## Rust / C 契约

新头文件 integrations/godot/bridge/include/ofe_v2.h 声明以下符号。返回值复用 ofe_status_v1，句柄按版本隔离，调用方传入的内存仅在调用期间借用。Rust 管理实例及单调句柄。每次 step 同时提交双方动作，校验全部输入再推进一帧，错误保留上一帧的全部可观测状态。第一个可提交帧为 1。

```c
int32_t ofe_v2_create(const char *p1_dir, const char *p2_dir, uint64_t *out);
int32_t ofe_v2_destroy(uint64_t handle);
int32_t ofe_v2_step(uint64_t handle, uint64_t frame, uint32_t p1, uint32_t p2);
int32_t ofe_v2_snapshot(uint64_t handle, uint8_t *out, uint32_t capacity, uint32_t *length);
int32_t ofe_v2_image(uint64_t handle, uint32_t image_id, uint8_t *out, uint32_t capacity, uint32_t *length);
```

目录参数为 NUL 结尾的 UTF-8 本地目录，分别调用 P3 Character::load，以 manifest 顺序绑定招式和几何到 Arena。双方 ID 1、2，分别使用 P3 双人场景相同的出生、移动、战斗线与能量设置。低八位输入依次为左、右、跳、切线、普攻、格挡、冲刺、保留。位 8–23 保存附加招式序号加一（零代表无指定）。互斥左右、普攻与指定招式并用、未知位和超界招式返回 INVALID_ARGUMENT。P2 四人接口继续由 Arena 与已有 CLI 覆盖。

snapshot 返回单帧 UTF-8 JSON，无尾随 NUL；image 返回 PNG 编码字节。容量不足时返回 OFE_LIMIT 并仅写所需 length，支持以 NULL、0 查询长度。成功写入实际 length。查询、重读及读取图像不推进实例或重复触发动画。一次成功 step 后重新读取同一批事件，呈现方按帧消费一次。不得输出 Rust 指针。

快照根含 frame、fighters、events、projectiles。fighters 按实体 ID 排序，每项含 id、team、x、z、h、facing、state、hp、max_hp、energy、max_energy 与 animation。state 使用 Rust 状态名。animation 含 clip（OFA ID）、index、image_id、rect（[x,y,width,height]）、origin（[x,y]）、events（有序字符串）。events 按核心事件顺序排列，每项含 kind（Rust 变体名，如 Hit、Blocked），以及变体对应的实体及数值字段。projectiles 含 id、owner、x、z、h。帧 0 可读到初始贴图。后续只在成功步进时消费 OFA tick；按小写状态名匹配 clip，缺少时回退 idle，再回退首个 clip。clip 切换从首帧开始。按 P3 已定义的 duration、循环、末帧和进入事件语义播放；如需无自引用所有权，可为现有播放器抽出共用的游标。图像 ID 在单实例内稳定，Godot 按 ID 缓存纹理并于关闭时释放。

## Godot 契约及交付

新增 RefCounted 类 OFEMatch，方法 open(p1_dir: String, p2_dir: String) -> int、close() -> int、step(frame: int, p1: int, p2: int) -> int、snapshot() -> Dictionary、image(image_id: int) -> PackedByteArray。snapshot 成功时附加 status=0，失败仅返回 status；无效图像返回空字节。C++ 负责 UTF-8、JSON/Dictionary 和缓冲区转换、RAII 关闭。GDScript 在固定 60 Hz 的 physics_process 中采集 InputMap，按明确帧序提交，显示角色位置、朝向、OFA 区域、原点和 HUD。舞台按可配置 α 从 X/Z/H 投影。AudioStreamPlayer 按已提交事件播放可辨认的音效。控制器离树时关闭句柄并清除纹理、重新入树可重建。

默认主场景为 res://match.tscn，自包含导出的技术场景以两份有效 OFC 目录或同一目录的双实例启动。允许外部本地目录。内置资源可从可信随包内容物化为供 Rust 读取的真实目录；必须验证 Godot 导出包脱离源码后亦能找到这些文件。显示用原始 PNG 字节来自 ofe_v2_image。使用原创的多帧 OFA 与可识别舞台，或对现有 CC0 角色夹具制作 P4 展示变体。P0 冒烟测试显式启动 proof，保留既有 --p0-test 导出测试。P4 增设 --p4-test，在编辑器运行时和导出程序中执行启动、动作、命中、状态、图像/动画、音频触发与重开检查。独立 QA 另外运行实际图形窗口并记录 60 FPS 下帧间隔与物理步数。

Rust 负责人维护 bridge/src、bridge/include/ofe_v2.h、桥接依赖与复用所需 Rust 模块。绑定负责人维护 extension 与 godot-profile。场景负责人维护 runtime 的场景、脚本及素材。主控集成 CI、CMake、入口兼容、导出和交付报告。QA 独立维护测试及采样记录。
