# ADR-004 · P1 双线对战模拟接口

项目负责人已确认启动 P1。本决议定义 Rust 侧的 MVP 契约，供 Combat Core、模拟器与 QA 使用。P0 C ABI v1 继续使用原有的单实体 Battle；对战模拟器直接调用同一个 ofe-combat-core crate 的公开 duel 模块。两处共享 Position、EntityId 与 TICKS_PER_SECOND。新增的攻击判定、双线动作及结算均由 Duel 唯实现。

## Rust 公共接口

下表和签名描述公共数据形状。以下结构体字段均为 pub，枚举变体大小写按表。Controls 实现 Default（中立输入）。Position 使用 crate 根部的既有定义。

```rust
Duel::new(config: DuelConfig) -> Result<Duel, DuelError>
Duel::step(&mut self, frame: u64, inputs: [Controls; 2]) -> Result<(), DuelError>
Duel::frame(&self) -> u64
Duel::fighters(&self) -> &[Fighter; 2]
Duel::events(&self) -> &[Event]
```

| 类型 | 字段或变体 |
|---|---|
| DuelConfig | fighters: [FighterConfig; 2], lane: LaneConfig |
| FighterConfig | spawn: Position, max_health: i32, walk_speed: i32, jump_speed: i32, gravity: i32, hurtbox: Rect, attack: AttackConfig |
| LaneConfig | startup: u32, travel: u32, recovery: u32, cooldown: u32, interruptible: bool |
| Rect | x: i32, h: i32, width: i32, height: i32 |
| AttackConfig | startup: u32, active: u32, recovery: u32, damage: i32, hitstun: u32, blockstun: u32, pushback: i32, hitbox: Rect, lane_rule: LaneRule |
| LaneRule | SameLane, CrossLane, BothLanes, DepthRange(i32) |
| Controls | axis: i32, jump: bool, switch_lane: bool, attack: bool, guard: bool |
| Fighter | id: EntityId, position: Position, health: i32, state: State, facing: i32 |
| State | Idle, Walk, Jump, Fall, LaneSwitch, Attack, Guard, Hitstun, Blockstun, Ko |
| Event | Moved { id: EntityId, position: Position }, StateChanged { id: EntityId, state: State }, Hit { attacker: EntityId, target: EntityId, damage: i32 }, Blocked { attacker: EntityId, target: EntityId }, Knockout { id: EntityId } |
| DuelError | InvalidConfig, InvalidInput, WrongFrame, Overflow |

Fighter 是当前帧的只读视图；内部计数、动作实例与已命中记录由 Duel 私有保存。实体槽 0/1 对应 ID 1/2，初始朝向根据 X 排序，X 相同时槽 0 朝右；facing 为 -1 或 1。两人位于不同队伍。P1 保留两个槽位的固定输入适配面，未来四人接口经单独决议扩展。

## 帧语义

启动时 frame=0。成功的 step 消费 frame()+1 的全部输入，原子更新双方和当帧事件。axis 限于 -1/0/1，动作布尔值表示本帧请求，guard 是本帧保持防御。无效输入、错误帧号与计算溢出保留双方、帧号和上一帧事件。配置必须拒绝无效尺寸、非正生命或跳跃参数、零有效/切线移动时长、负伤害、非法出生深度以及非法纵深范围。

同一 tick 先处理动作/位移，再针对同一份双方状态检测命中，最后统一应用结果；一人倒下仍应用另一人已登记的命中。矩形为整数 X/H 半开区间，边接触不命中；本地 x 按攻击朝向镜像。X 增大向右，H 增大向上，近线 Z=0，远线 Z=1000。切线启动、移动、结束分别持续相应帧数，移动阶段整型插值，最后到达目标；随后冷却。SAME_LANE 与 CROSS_LANE 使用最近线（Z=500 取后线），分别命中同线与异线；BOTH_LANES 跳过线筛选；DEPTH_RANGE 使用实际 Z 距离的闭区间。interruptible 控制切线受击后是否中止动作；中断时归入最近线。普通攻击从动作启动 tick 起从零计龄，启动后的 active 帧检测一次有效命中/格挡，每个动作实例最多命中同一目标一次。P1 格挡伤害为零。生命下限为零。致命一击终止切线时归入最近线。pushback 是按出招朝向计算的有符号位移，负值可将目标拉近；以加宽整数计算，再检查坐标范围。

## OFC 与外部配置适配

Rust 核心只接收上述原生数据。模拟器把本地验证通过的两个 OFC manifest、各自 attributes、moves、hitboxes 与场景参数转换为 DuelConfig。max_health 来源于 attributes；普通攻击启动、有效、恢复、伤害、硬直、格挡硬直、击退及双线规则来自所选招式。hit/hurt 矩形来自角色 hitboxes；场景侧提供出生点、walk_speed、jump_speed、gravity 和 lane 参数。夹具需要显式提供一个 hit 和一个 hurt。P0 既有格式 1.0 sample 保持可校验；P1 模拟器拒绝不能提供上述必要数据的战斗输入。角色 ID、路径、安全资源解析、文件 IO 与 JSON 不进入 combat-core。P1 支持的普通招式可限定 hitstop、armor、energy_cost、invulnerability 为 0 且 cancel_windows 为空；适配器应为不支持的值给出错误。完整 OFC 运行时与四人对战由后续阶段接入。
