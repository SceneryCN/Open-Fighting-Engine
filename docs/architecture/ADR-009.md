# ADR-009 · Arena 确定性、快照与录像

P6 以战斗核心的已提交帧作为记录边界。输入、战斗规则、帧计数、逐帧随机流、战斗结算状态均由 Rust 所有。沿用现有 60 Hz 固定帧及按实体 ID 排序的同时结算顺序。P0、P1 和 P5 的操作语义保持兼容。[总纲第四章与 P6](../governance/PROJECT_CHARTER_V1.0.md)

## 核心接口

Arena::with_seed(config, seed) 使用显式 u64 种子。默认构造使用种子 0。采用 SplitMix64：每个成功提交的 tick 将流状态加上 0x9e3779b97f4a7c15（模 2 的 64 次方），random_sample() 读取当前流状态的混合输出。重复读取、失败步进和暂停均不消耗随机数。现有招式保留其配置定义的固定伤害。快照保存流的当前位置，恢复后可以继续产生相同样本。

checkpoint() 捕获 ArenaSnapshot；from_checkpoint(&snapshot) 创建独立实例，restore(&snapshot) 原子替换相同规则的现有实例。快照含版本、排序后的完整 ArenaConfig、frame、rng_state、infinite_health、World 和当前帧事件。World 包含动作时钟与速度、切线冷却、受击/格挡状态、攻击实例与有效窗口、消耗目标掩码、护甲、命中确认、逐对连击、能量、投射物剩余寿命与来源和最后分配的实例 ID。暂存缓冲区、空闲优化标志和表现层可派生状态不序列化。读取时检查快照版本、规则、各槽及内部索引、几何方向和生命周期约束，失败保持既有实例完整。

state_hash() 返回 u64 FNV-1a。V1 规范输入由固定 ASCII 域 OFE-ARENA-v1、按字段声明与实体 ID 顺序编码的紧凑规则 JSON、再加紧凑数组 [frame,rng_state,infinite_health,world,events] 构成。所有数据为整数、布尔、枚举、定序结构及数组。共享固定版本 serde/serde_json，取类型序列化字节，不依赖输入文件的缩进与对象键顺序。预计算规则的 FNV 中间状态；常规步进按需提供状态哈希。哈希供确定性比较，图像、音频、地址、渲染与和求值无关的缓存均在比较范围外。

## 录像

OFE_REPLAY v1 使用 UTF-8 JSON 保存起始快照、其哈希及逐帧已接受的命令和预期哈希。哈希以零填充到十六位的小写十六进制表示。起始快照内嵌已解析规则，可在其他桌面平台独立运行。CLI 和 Godot 共用 Rust 录像编码与验证实现，对照已记录的每一步，遇到第一处差异返回帧号和预期/实算值。Godot 从与录制角色兼容的场景播放，其表现流程继续使用 OFC/OFA。磁盘结构见 [OFE_REPLAY Schema](../../formats/replay/schema.json)。录像文件只能在成功验证后作为回放输入，失败时保留当前训练和已有输出。

可复制快照和独立输入记录为后续预测、重演预留接口。网络传输与联机调度仍按总纲排期。
