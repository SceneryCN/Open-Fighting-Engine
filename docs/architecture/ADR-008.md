# ADR-008 · 离线示范游戏与训练观测

按[总纲第八章及 P5](../governance/PROJECT_CHARTER_V1.0.md)交付。默认进入示范主菜单。选人、VS、暂停、结果、训练控制、设置、背景音乐和舞台属 Godot；生命、能量、状态、位置、招式和命中属 Rust。胜负由存活队伍数确定；全灭为平局。暂停和结果页面冻结原生帧。训练记录每个成功步进的完整输入，从同一阵容与初始条件重新创建并回放。P6 的持久化回放、快照恢复、哈希诊断另行实施。

## 对战与兼容性

P4 的双人适配器固定两个角色和输入，但下层 Arena 已支持四人和队伍。以 ABI v2 增量符号扩展既有 OFEMatch；保留旧入口、输入位、包目录和快照字段。open_roster(dirs: PackedStringArray, mode: String) 接受 duel / training 两人或 team / ffa 四人。按目录顺序分配 ID，从 1 开始；team 的队号为 1、1、2、2，其余各占一队。step_roster(frame: int, masks: PackedInt32Array) 一次提交全员，长度须与阵容相同。set_infinite_health(enabled: bool) 仅用于训练局，启用期间打击仍有伤害事件与硬直，原生生命不再扣减。三个方法都返回原有状态码。C 接口原型见 ofe_v2.h。旧 open 和 step 保持双人语义。各模式的开局与重置由公开接口加载选中的 OFC。OFC 招式声明可选非负整数 launch_speed；发动时设置施术者上升速度，随后按场景重力逐帧移动。

所有模式从第零帧开始，在每位 fighter 的快照中返回整数 move_count，其值为该角色 OFC 清单中的招式数。输入层根据各席位的 move_count 过滤无对应招式的按键，以兼容仅配置普攻的外部角色。

## 训练快照

训练局每位 fighter 增加 move_id（空串代表没有招式）、move_age（当前招式零基帧，无招式为零）、startup、active、recovery（当前招式配置帧数），hitstun、blockstun（当前剩余帧）、combo（当前连击）、damage（最近一次由该角色造成的单次命中伤害，初始为零）和 boxes。框由 kind、x、z、h、width、height 表达；x、h 是左下角世界坐标，朝向已应用。hurt 和 push 取自 OFC；hit 用于有效攻击窗口。训练界面叠绘原生框，显示生命、能量、坐标、状态和上述指标。假人站立、防御、受击，无限生命、重置、慢速、单帧、记录和回放均通过同一个训练实例生命周期。

## 验证

真实编辑器运行与独立导出均需验证选人 → VS → 对战 → 胜负、返回主菜单、训练和暂停。独立 QA 使用原生快照核对队伍、伤害、框和训练帧；检查原创舞台、背景音乐、双角色的攻击范围、节奏、特殊技、超必杀及取消路线。采样图形帧间隔和物理步耗时，报告样本、运行环境及极值。保留 P0/P4 专用启动参数和自动化覆盖。负责人最终验收。
