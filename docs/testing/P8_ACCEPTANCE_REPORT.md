# P8 桌面发行候选与默认键位 · 独立 QA

在 Apple M1 Max、macOS ARM64、Godot 4.7.2 上，编辑器、Release 导出程序和仓库外解包的应用都通过了新的物理键位回归。独立测试通过 Godot 的物理键按下与释放事件驱动引擎；未做实体键盘矩阵防冲突测量。[运行记录](evidence/p8-release.json)

## 键位与原生战斗

从主菜单进入四人自由混战，对 37 个不同的物理键逐个按下、释放，核对四席传入核心的命令掩码。P1 的 W 跳跃、S 换线、A/D 移动；J 和 O 普攻，K 防御，L 冲刺，U 特殊技，I 超必杀。P2 的方向键和 F/G/H/R/T 对应各自席位，其他两席的键位也全部通过。在同一时刻按住 P1 移动加防御、P2 普攻、P3 特殊技、P4 冲刺，四个命令同时成立，松开后全部归零。

重新开局后分别按下 J、O、U、I、F、R、T，实际 Rust 战斗返回七次对应席位和招式索引的 Started 事件。Godot 测试框架已增加脚本异常判定。仓库外应用同时通过 P0、P4、P5、P6 与 P7 外部角色验证，包含保存后重启回放及 CLI 独立复算 25 帧。

## 图形帧间隔

两个 Release 图形窗口各预热 120 帧，再以两位外部角色采集 600 个绘制间隔。限速 60 FPS，渲染器为 OpenGL 4.1 Metal Compatibility。

|运行方式|平均 FPS|P95|P99|最长|超过 25 ms|同期模拟 tick|
|---|---:|---:|---:|---:|---:|---:|
|独立导出|59.512|19.153 ms|20.787 ms|70.547 ms|4|606|
|从归档解包|59.993|20.339 ms|21.718 ms|23.341 ms|0|600|

第一次采样出现较长绘制间隔，原因尚未确定。两轮结果均保留。其他平台的 GPU 帧率需要实机测量。

## 发行包

本机重新生成 0.1.0-rc.1 的游戏、模拟器与通用作者包，核对 RELEASE.json、源码提交、许可证文件、原生二进制架构和 SHA-256。macOS 游戏与扩展均为 ARM64 Mach-O。游戏、模拟器和作者包中 LICENSES 目录下分别有 29、27、3 份文件，作者 SDK 及示例代码另附 MIT 许可。解包程序和模拟器均成功运行。机器记录中的三个摘要对应 QA 本机生成物，分发包摘要取自相应构建的 SHA256SUMS。[安装与运行](../p8/INSTALL.md)

复现键位检查可在编辑器运行 `Godot --headless --path integrations/godot/runtime -- --p8-test`，导出程序运行 `OFE --headless -- --p8-test`。完整回归沿用 `scripts/test/headless.py`。帧间隔可通过 `python scripts/test/p7_author.py OFE.app --exported --pacing` 复测。跨平台候选构建证据见[本阶段交付报告](../../DELIVERY_REPORT.md)。最终签收由项目负责人决定。
