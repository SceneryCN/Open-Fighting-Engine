# P0 风险与处置
|风险|观察证据|处理与剩余责任|
|---|---|---|
|首次从空缓存发现扩展时编辑器退出崩溃|macOS ARM64，4.5 与 4.7 API 绑定均出现退出信号 11|Build 通过 install 预登记扩展；清理缓存后重新安装。QA 验证干净检出；若上游修复，先重复对照测试再修改 ADR-003|
|跨架构运行环境存在差异|Intel macOS 使用 Rosetta，Linux 使用 x64 容器，Windows 本地检查使用兼容环境|Build 记录目标文件格式与哈希，QA 按实际运行层级签注；原生托管任务留待关联远端|
|CI 配置与托管工具镜像可能偏离本地验证|当前仅有本地 Git|项目负责人关联后触发 P0 workflow；QA 核查 quality 与四个 proof job 的日志和产物|
|ABI 升级破坏调用者或错误状态|v1 的版本、结构大小、句柄和输入约束跨三种语言|架构负责人对 ABI 修改先建 ADR，QA 重跑短缓冲区、旧句柄和错误原子性测试|
|开发样例覆盖的工作量有限|基准只测单实体空场景输入和状态|P0 按骨架评估。后续四人碰撞与同帧结算需在获得下一阶段授权后单独测试|
|分发时遗漏许可证与对应源码|Windows 及模板含多方运行时代码|对外发布时由发行负责人逐包核对源码、许可证与声明；本轮仅供本地工程验收|
