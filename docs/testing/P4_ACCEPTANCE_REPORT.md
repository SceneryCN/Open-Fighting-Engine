# P4 独立 QA · Godot 对战场景

独立工作树从 ADR-007 构建 Rust 静态库、C++ GDExtension、Godot 编辑器项目和 macOS ARM64 发布程序。主机为 Apple M1 Max，Godot 4.7.2 stable，Rust 1.100.0。P4 验收使用两名本地玩家的真实 Arena。最终签收由项目负责人决定。

|项目|检查与实测|
|---|---|
|C ABI v2|独立 C 调用方验证 v1/v2 句柄隔离、短缓冲区报告精确长度且不改动原内容、错误输入与错误帧号保持快照逐字节相同、重试成功、销毁旧句柄、再次打开返回新标识。工作区 Rust 74/74 项测试通过，CTest 3/3 项通过。|
|输入到战斗|映射普攻产生 Hit 并减少对手 HP；玩家二格挡得到 Blocked，HP 保持；验证实际键盘移动映射，跳跃及切线分别改变原生 H/Z 和屏幕角色位置。|
|呈现与音频|两个 Sprite2D 按 OFA 原点、朝向及区域取图，攻击期间动画状态切换；HUD 的生命值和上限与快照一致，命中时 AudioStreamPlayer 带有效流且处于播放状态。|
|项目与场景生命周期|对战重开回到帧 0；离树后旧原生对象不可再读，缓存释放，重新入树后推进新战斗。编辑器实际运行产生 OFE_REENTRY_PASS、OFE_P0_PASS、OFE_P4_PASS。|
|外部数据|从临时工作目录启动同一引擎，通过命令行载入两份独立角色并分别改成 137 和 191 HP、P1 普攻 23 伤害。目标降到 168，HUD 同步；等待音效结束后退出，详细日志通过，无 ObjectDB 泄漏提示。|
|发布入口|macOS ARM64 导出程序从源码目录以外启动。内置 OFC、Rust 图像字节和默认对战场景随应用分发，两条发布冒烟分别输出 OFE_P0_PASS、OFE_P4_PASS。|

截图来自运行中的 Godot 窗口，取自命中后的 Attack / Hitstun 帧。初版截图暴露出血条遮盖数值，调整后重新截图确认。外部目录测试在命中后立即退出时，Godot 报两个尚在播放的 WAV 对象；等待短音效自然结束并释放场景后复测通过。[实际对战画面](evidence/p4-match.png)

## 图形窗口帧时间

启用 Compatibility 渲染器，960×540 视口，每轮预热 120 帧后采样 600 次 frame_post_draw 间隔，渲染上限 60 FPS。两种脚本均驱动真实 InputMap。持续攻防交替格挡并播放反馈音，频繁重开脚本每 64 个物理 tick 重建一次战斗，同时产生击中和跳跃。独立探针核对每个物理 tick 恰好推进一个原生帧，并从输入提交前到对战节点处理后采集主线程墙钟时间。截图在预热期采集。

|负载|FPS|物理 tick|命中 / 格挡|绘制 P99 / 最大 ms|超过 25 ms|物理处理 P99 / 最大 ms|
|---|---:|---:|---:|---:|---:|---:|
|持续攻防|59.925|601|0 / 56|39.532 / 45.868|62|1.125 / 2.200|
|频繁重开|60.023|600|30 / 0|23.877 / 30.188|2|6.424 / 15.576|
|持续攻防|59.995|600|0 / 56|20.703 / 31.114|2|1.531 / 6.645|
|频繁重开|59.846|603|30 / 0|24.646 / 60.255|5|6.981 / 15.190|


两种负载的平均绘制速率均接近 60 FPS，部分绘制间隔超过 16.667 ms。在该主机上，持续攻防的物理处理耗时低于绘制间隔；频繁重开时，还包含同步加载 OFC、创建实例、解码 PNG 及上传贴图的开销。原始记录包含每次重开的实测耗时。帧后回调衡量引擎绘制提交间隔，屏幕扫描显示时刻与音箱输出延迟未单独测量。[逐轮原始记录](evidence/p4-frame-pacing.json)
