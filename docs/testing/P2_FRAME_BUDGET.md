# P2 战斗模拟帧预算复核

**本机四人模拟在本次全部受测负载中达到 60 Hz 的 16.667 ms 每帧预算。** 2026-11-26，macOS 27.3 ARM64，Apple M1 Max，Rust 1.100.0 release。本次比较优化前核心 21856c1 与优化后核心 e0dea65。每版执行三轮，单轮包含四组各 6,000 个稳态 tick，以及 200 次同帧投射物集中命中，共 72,600 次计时。两版各观测到 0 次超预算。基线同样满足这些负载的预算，优化进一步降低了开销。

## 工作量与验证边界

- 每次只计 Rust 的一次 Arena::step。计时使用 Instant 的墙钟耗时，比较条件为耗时纳秒数 × 60 > 1,000,000,000。数据构造、资源解码、统计、轨迹比较与终端输出均在计时区间之外。基线和优化版分别冷启动进程，依次按 A/B/B/A/A/B 执行。
- 四人 FFA 通过公开配置与正常输入产生工作量。互击组每个 tick 实际结算 12 个有向命中，单轮合计 72,000 次。两个持续投射物场景每 tick 由四人各发射一个，先按 256 或 1,024 tick 寿命预热，逐帧校验存活数恒为 1,024 或 4,096。每轮各有 24,000 次命中和 24,000 次生成。
- 集中命中组预热至 4,096 个存活投射物，目标保持无敌。下一帧停止施放，4 个到期，其余 4,092 个各命中 3 个对手，同一 tick 结算 12,276 次。每轮从相同预热状态独立取样 200 次，克隆预热世界的时间排除在外。连续采样组不重置世界。
- 单独的轨迹运行逐帧哈希全部公开 fighter、排序后的 events、投射物 ID/owner/X/Z/H 及帧号。相同驱动和 6,000 帧输入在两版的全部七项摘要逐字节相同。包含两个失败后重试案例：末位角色冲刺产生位移溢出，以及结算至末位目标才发生击退溢出。重试与无错误历史的对照场景逐帧比对，失败帧保留先前可观测状态。[对照摘要](evidence/p2-frame-traces.txt)
- 此计时覆盖受测硬件上的 P2 权威模拟。窗口绘制、输入设备、图形驱动、展示线程及实际显示器呈现间隔需由对应的宿主场景单独验证。未为任意输入规模、后台负荷和任意机器建立最坏执行时间上界。

## 复现

从仓库根目录，使用同一个 frame_budget.rs 对两个版本构建。基线 21856c1 工作树需要从本次交付拷入该 example；优化后的工作树可直接运行。release 二进制位于 target/release/examples/frame_budget。轨迹必须分别生成，在计时进程结束后比较。

```sh
cargo build --locked --release -p ofe-sim --example frame_budget
target/release/examples/frame_budget --frames 6000
target/release/examples/frame_budget --trace --frames 6000
```
